# AI 演示工作台

两个板块：**项目简报**与**交付给 Codex**。提供初步 PPT 和简报，Codex 以原稿内容为基础渲染交互式 HTML 演示全稿。无需逐页录入数据、走六步流程或先确认两页样张。

## 启动

需要 Node.js 18 或更新版本。在仓库根目录运行：

```sh
node dashboard/serve.mjs --port 8001
```

打开 `http://127.0.0.1:8001/dashboard/`。不需要安装前端依赖或配置 API 密钥。请通过本地服务打开，避免 file 协议限制。端口被占用时可指定其他端口。

## 使用

1. **项目简报**：填写业务目标、受众、品牌、区域、语言、信息密度与视觉方向。页数仅作参考，优先保持原稿内容完整。
2. 上传初步 **PPTX、PPT 或 PDF**，可补充重点修改说明。上传 **JPG、PNG、WebP、GIF** 照片，可预览原图、填写用途或对应页，并可移除、撤销。单个文件不超过 25 MB，最多 20 个，合计不超过 40 MB。
3. **交付给 Codex**：补充设计和交互要求；完整任务说明可展开编辑。点击「准备项目包，交给 Codex」，再点击「在 Codex 中继续」，发送预填任务。
4. Codex 根据简报、初稿及照片，制作可切页、键盘导航、全屏播放、支持适当图表交互和编辑保存的 HTML 全稿。原稿只有图表截图且无法可靠提取数值时，保留原图并在 QA 说明，不猜数值。

点击「保存项目与附件」下载 `project.json`，含所有附件的 base64 内容；导入可完整恢复。静态托管时可将此 JSON 和下载的任务说明一起提供给 Codex，任务说明包含附件解码方法。本机项目包会直接提供附件文件，便于读取。

## 本机项目包

每次准备创建独立目录 `dashboard/exports/handoffs/<时间-随机ID>/`，包含：

- `project.json`：简报、设计要求、附件及旧项目的兼容数据。
- `assets/`：实际初步 PPT/PDF 和照片，以附件 ID 与扩展名命名。
- `assets.json`：原文件名、用途与实际路径，不含重复 base64。
- `fancy-prompt.md`、`handoff.md`：本轮 HTML 全稿制作要求。
- `SKILL.md`、`references/`：自包含的制作方法。
- `sources.csv`：旧项目保留的来源台账；登记的路径不代表对应原件已复制。
- `bundle.json`：项目版本、附件数量及「生成尚未启动」状态。

交接任务明确：基于上传初稿和简报直接制作全稿，本轮范围优先于 skill 默认分阶段流程；默认交付 HTML，PPTX 仅在额外要求时生成。不会用看板的旧占位模板页覆盖原稿。

Codex 桌面链接预填任务与目录，不会自动发送或启动模型。若设备未注册链接处理器，可手动在 Codex 打开界面显示的目录，发送「请读取 handoff.md，完成交互式 HTML 演示」。成品和 QA 在该目录的 `outputs/` 中，看板不自动回收或显示模型执行进度。修改简报、附件或设计要求后，旧交接入口失效，须重新准备材料包。

## 保存与兼容

- 简报及附件使用当前站点的 IndexedDB 本地保存；附件数据与简报元数据分开写入，编辑文字无需反复写入大文件。浏览器限制、清除数据或更换地址仍可能导致缓存不可用，请另存 JSON。
- 自动兼容旧版 localStorage 和旧项目 JSON，保留原有页面、来源和复核记录；旧流程提示词自动清除，避免继续要求两页样张。移除的三个工作区不再作为操作步骤。
- 附件只在本机浏览器与本地服务间传输，不上传到云端。后续 Codex 按其环境和权限读取材料。不要把项目文件或 `exports/` 提交到公开仓库。
- 本地服务仅监听 `127.0.0.1`，检查 Host、Origin 和会话令牌，验证附件类型、大小和文件头；不接受任意输出路径或命令。导出目录不通过静态服务公开。
- 可将 dashboard 目录静态托管，无构建步骤；静态模式可编辑、上传和下载 JSON，无法写入本机交接目录。不要公开 `exports/`。

## 开发与检查

```sh
node dashboard/test.mjs
node dashboard/handoff.test.mjs
```

`app.mjs` 管理两板块界面、IndexedDB 和上传；`assets.mjs` 校验附件；`handoff.mjs` 生成 HTML 全稿任务；`serve.mjs` 准备实际文件包。`model.mjs`、`chart.mjs` 与 `draft.mjs` 保留旧项目数据兼容和相关测试。

测试涵盖两板块、旧项目迁移、附件格式与大小限制、较大 base64 内容、文件内容完整性、版本目录和本地服务访问限制。HTML 的实际制作与播放验收仍需在 Codex 完成，准备材料包不能称为 HTML 已生成。
